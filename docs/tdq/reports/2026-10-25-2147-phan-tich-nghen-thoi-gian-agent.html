💥 3. Chi Tiết 4 Căn Nguyên Gây Nghẽn Nghiêm Trọng

1. Blast Radius > 60% Kích Hoạt Full Suite Trọng yếu

Trong scripts/tdq_test.py, quy tắc NGUONG_TRON_BO = 0.6 quy định nếu vùng ảnh hưởng AST vượt 60% module, hệ thống tự động chạy toàn bộ suite thay vì chạy targeted test.

if everything and len(chosen) >= NGUONG_TRON_BO * len(everything): return everything, "radius %d/%d modules reaches the 60% threshold"

Hậu quả: Khi sửa các file trung tâm như tdq_setup.py, toàn bộ 2,978 tests chạy mất 638 giây (~10.6 phút). Do timeout của Bash tool là 120 giây, tiến trình bị ngắt và đẩy vào background, khiến agent bị treo turn hàng chục phút.

2. Archify Headless Pipe Timeout trên Windows Trọng yếu

Mỗi khi chạy tdq_finish.py hoặc chốt spec/plan có Archify, hệ thống mở headless Chrome với cờ --remote-debugging-pipe để kiểm tra DOM sơ đồ.

Chrome DevTools read pipe failed: stream ended Windows browser startup may have relaunched before connecting

Hậu quả: Trên Windows với tài khoản Admin (Process Elevation), sandbox của Chrome relaunch tiến trình làm đứt gãy pipe của hệ điều hành. Hệ thống phải chờ timeout từ 1.5s đến 5s cho mỗi view (Master Map 4 view mất 15-20s mỗi lần gọi finish).

3. Phình To Context & Trượt Prompt Cache Ảnh hưởng AI

Tổng kích thước context nạp thường trực vào agent qua SessionStart lên tới hơn 115 KB (~38,400 tokens):

.remember/today-2026-10-25.md: 11,636 bytes (~3,878 tokens) docs/workinglog/2026-10-25.md: 13,740 bytes (~4,580 tokens) CLAUDE.md + luật + tools: ~25,000 tokens

Hậu quả: Context quá lớn làm độ trễ sinh từ (Inference Latency) của LLM tăng từ 3s lên 30s – 50s mỗi turn. Nếu một request có 30 turns, thời gian chờ mô hình trả lời đã mất từ 15 đến 25 phút.

4. Vi Phân Thủ Tục Quá Nhiều Lượt (Deep Mode) Thủ tục

Trong Deep Pipeline (như request 11 tasks vừa qua), mỗi task đều bắt buộc chuỗi thủ tục:

Đổi plan [~] ➔ Viết mã ➔ Chạy test ➔ Đổi plan [x] ➔ Ghi workinglog ➔ tdq_finish

Hậu quả: 11 tasks nhân lên tạo thành hơn 55 lượt gọi công cụ. Các chốt chặn lint markdown nghiêm ngặt (như Luật R5 ngắt câu >40 từ, hash manifest mismatch) khiến agent phải dừng lại sửa lặt vặt nhiều lần.

🚀 4. Lộ Trình Đề Xuất Giải Pháp Khắc Phục Triệt Để

  • 1

    Phân tầng Test Suite & Không chạy 100% ở Implement

    Chỉ chạy smoke tests và các test liên quan trực tiếp (< 50 tests, runtime < 10s) trong pha implement. Chỉ kích hoạt 100% full suite (2,978 tests) ở pha QC cuối cùng hoặc khi người dùng chọn mức QC ultra.

    Tiết kiệm 15 – 30 phút mỗi request
  • 2

    Kích hoạt chạy test song song đa nhân với pytest-xdist

    Cấu hình pytest -n auto trên Windows để tận dụng tối đa số luồng CPU của máy. Rút ngắn thời gian chạy toàn bộ 2,978 tests từ 10.6 phút xuống dưới 2.5 phút.

    Tăng tốc độ chạy test lên gấp 4 lần
  • 3

    Vá kết nối Archify trên môi trường Windows Elevated

    Khi phát hiện Windows Admin (Elevation), Archify tự động chuyển sang xác thực static hash offline hoặc kết nối qua Chrome DevTools MCP (Port 9222) thay vì spawn process với pipe headless.

    Tiết kiệm 20 – 60 giây mỗi lần kết thúc turn
  • 4

    Cắt tỉa bộ nhớ Remember & Giữ ấm Prompt Cache

    Tự động nén tệp .remember/today-*.md dưới 4KB trong context tiêm vào phiên làm việc, chỉ lưu tóm tắt 3 giờ gần nhất. Duy trì nhịp gọi của agent trong vòng 270 giây để không bị trượt prompt cache TTL (300s).

    Tiết kiệm 5 – 15 phút thời gian chờ mô hình
