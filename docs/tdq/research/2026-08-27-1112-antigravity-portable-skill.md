- Rút ra: Xác nhận đúng chuẩn Claude Code — mỗi skill là 1 thư mục con chứa `SKILL.md` (bắt buộc, YAML frontmatter `name` + `description` tối thiểu, có thể thêm `metadata.category`) và tuỳ chọn `scripts/`, `references/`, `assets/`. Frontmatter được đọc ở startup (progressive disclosure: layer 1 chỉ đọc frontmatter, layer 2 đọc toàn bộ SKILL.md khi task khớp `description`, layer 3 mới đọc scripts/references). Global path chính thức theo docs mới nhất: `~/.gemini/antigravity-cli/skills/<skill-name>/SKILL.md`. Tuy nhiên **có nhầm lẫn/không nhất quán giữa các nguồn** (bài atamel.dev 2026-07-01 liệt kê ít nhất 3 path global khác nhau tuỳ tài liệu AGY/AGY CLI/AGY IDE: `~/.gemini/antigravity-cli/skills/`, `~/.gemini/antigravity/skills/`, `~/.gemini/skills/` (shared), `~/.gemini/config/skills/<plugin>/`) — do sản phẩm đang tái cấu trúc liên tục trong nửa đầu 2026. Đồng thời còn có `npx skills` cài vào `~/.agents/skills` — path này Antigravity 2.0/IDE đọc được nhưng **Antigravity CLI (agy) thì KHÔNG** đọc trực tiếp, phải copy sang `~/.gemini/antigravity-cli/skills/` (global) hoặc `<project-root>/.agent/skills/` (project, lưu ý là `.agent` số ít theo bài Medium, khác với `.agents/skills/` số nhiều dùng trong docs chính thức — một nguồn khác không nhất quán nữa). Có bug đã báo cáo: symlink/junction trỏ vào skill folder trên Windows khiến `/skills` liệt kê 0 skill dù skill vẫn gọi được trực tiếp qua `@skill-name`.

## Truy vấn 2: Cơ chế chặn/gate tool call (hooks, permissions)
- Nguồn: https://antigravity.google/docs/hooks ; https://antigravity.google/docs/cli/permissions ; https://antigravity.google/docs/cli/commands/permissions ; https://antigravity.google/docs/cli/features
- Rút ra: **Kiến thức cũ trong repo đã LỖI THỜI — agy hiện đã có hệ thống hook đầy đủ**, tương đương PreToolUse/PostToolUse của Claude Code. Cấu hình tại `hooks.json` trong thư mục customization (`.agents/` cấp workspace, hoặc `~/.gemini/config/` cấp global — lưu ý lại một path global khác, không phải `antigravity-cli/`). 5 event: `PreToolUse`, `PostToolUse`, `PreInvocation` (trước khi gọi model), `PostInvocation` (sau mỗi lần gọi model), `Stop` (khi loop kết thúc). Hook nhận JSON qua stdin, trả JSON qua stdout. `PreToolUse` output có field `decision`: `allow` | `deny` (chặn cứng ngay lập tức) | `ask` | `force_ask` | `deny_unless_prior_grant` — đây chính là cơ chế gate cứng cần cho thiết kế "không được bỏ qua bước". `PostInvocation` có `terminationBehavior: force_continue` để ép loop tiếp tục nếu agent định dừng sớm. `Stop` hook có thể trả `decision: "continue"` để ngăn agent dừng khi chưa xong việc — rất hợp để enforce "chưa chạy hết plan thì không được kết lượt" giống cơ chế TDQ đã làm cho Claude Code. Song song đó có **Fine-Grained Permissions Engine** riêng (không phải hook) cấu hình tại `~/.gemini/antigravity-cli/settings.json`, dạng `action(target)` (`read_file`, `write_file`, `read_url`, `execute_url`, `command`, `unsandboxed`, `mcp`) với 3 danh sách `allow`/`deny`/`ask`, mặc định workspace auto-allow, còn lại default `ask`. Muốn ép "chỉ 1 tool được ghi state" có thể kết hợp: permission `deny` toàn bộ `write_file(*)`/`command(*)` trừ 1 lệnh gọi MCP tool cụ thể, cộng thêm `PreToolUse` hook double-check.

## Truy vấn 4: Workflows/slash-command ép chuỗi bước cố định
- Nguồn: https://antigravity.google/docs/rules-workflows ; https://discuss.ai.google.dev/t/agents-not-reading-workflow-when-directed-with-slash-commands/115448 ; https://antigravity.google/docs/cli/reference
- Rút ra: agy có "Workflows" — file markdown lưu các bước, gọi qua slash-command `/workflow-name`, có thể gọi lồng nhau (`/workflow-1` gọi `/workflow-2`). Đây CHỈ LÀ prompt injection theo trình tự (giống skill/prompt macro), **không phải cơ chế ép buộc kỹ thuật** — model có thể tự quyết định có đọc/tuân theo hay không. Bằng chứng thực tế: bug report agy 1.14.2 "agents thường xuyên bỏ qua đọc workflow" vì system prompt dùng cụm "if a workflow looks relevant" (mang tính discretionary), khiến model tự quyết có mở file workflow hay không dù user gõ đúng slash-command. Google xác nhận đã fix ở bản mới hơn nhưng cho thấy: **workflow không đảm bảo "never skip"** — chỉ là gợi ý mạnh, độ tin cậy phụ thuộc version và có lịch sử regress. Muốn ép cứng thực sự phải dùng hook (`PreToolUse`/`Stop`) hoặc permission `deny`, không dựa vào workflow/slash-command đơn thuần.

## Hệ quả thiết kế
1. **Không dựa vào workflow/slash-command hay độ dài AGENTS.md/SKILL.md để "không bao giờ được bỏ qua"** — cả hai đều chỉ là gợi ý cấp prompt, có model discretion và có lịch sử bug bỏ qua thực tế đã xảy ra trên agy. Bundle phải dùng **hook `PreToolUse`/`Stop`** làm lớp ép buộc kỹ thuật thật sự (agy đã hỗ trợ, xác nhận qua docs chính thức 2026), tương tự cách TDQ đã làm cho Claude Code — không còn là "không có cơ chế" như hiểu biết cũ trong repo, CẦN CẬP NHẬT lại giả định này.
2. Thiết kế gate cụ thể: viết 1 script hook nhỏ (bash/node) đọc `toolCall.name`/`toolCall.args` từ stdin, kiểm tra state file (ví dụ trạng thái plan/spec JSON tương tự `tdq_state.py`), trả `{"decision":"deny","reason":"..."}` nếu bước bắt buộc trước đó chưa hoàn tất. Đặt trong `hooks.json` — nhưng vì path global cho hooks không thống nhất giữa các bản (`.agents/` vs `~/.gemini/config/`), bundle nên cài cả workspace-level (`.agents/hooks.json`) lẫn thử global, và luôn kèm hướng dẫn user tự kiểm tra bằng `/permissions` hoặc log.
3. Dùng thêm `Stop` hook trả `decision:"continue"` để chặn kết lượt sớm khi state cho biết còn task plan chưa chạy — đúng tinh thần "cổng chặn kết lượt" đã làm cho Claude Code (xem commit `2773af7`), giờ có thể port sang agy.
4. Permissions engine (`settings.json`) dùng làm lớp phòng thủ thứ 2: `deny` các `write_file(*)`/`command(*)` rủi ro cao, chỉ `allow` qua 1 MCP tool cụ thể nếu muốn ép "mọi thay đổi state phải qua script/MCP tool duy nhất".
5. Vì các đường dẫn global (skills, hooks, mcp_config, settings) đang KHÔNG ổn định giữa các bản/tài liệu agy (nhiều path khác nhau ghi nhận trong cùng khoảng 2026-05 → 2026-08), bundle nên: (a) cài vào TẤT CẢ các path ứng viên đã biết (không chỉ 1), (b) kèm 1 bước "self-check" trong SKILL.md yêu cầu agent tự chạy `/skills`, `/mcp`, `/permissions` để xác nhận đã được nạp đúng trên máy đích, thay vì giả định tĩnh 1 path là đúng.
6. MCP: cài `mcp_config.json` ở cả `~/.gemini/config/mcp_config.json` (path mới) và `~/.gemini/antigravity-cli/mcp_config.json` (path legacy, được xác nhận agy vẫn đọc) để tránh rủi ro như issue #60 (project-local bị bỏ qua ở một số bản).
